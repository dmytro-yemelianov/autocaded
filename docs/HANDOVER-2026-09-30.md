## Confirmed implementation state

The recovered command table has 57 names. `TABLET`, `PLOT`, and `QPLOT` are
hardware-dependent exclusions; the native editor recognizes all other 54
names. Recognition is a dispatch milestone, not proof of compatible behavior.

The recent command slice includes:

- `?`, `HELP`, `FILES`, and `MENU` entry behavior; MENU parses `.MNU` labels and
  preserves macro bytes. On-screen rendering and mouse-click dispatch of the
  parsed menu is implemented on the not-yet-merged `worktree-screen-menu-rendering`
  branch (see Checkpoint above) — not yet in `main`;
- `DELAY`, `RES`, `RESOLUTION`, `RESUME`, and `UNITS` state and prompts;
- `DIM` prompt flow and primitive LINE/SOLID/TEXT geometry for the observed
  linear cases; HATCH pattern help/scale/angle/selection prompts; and SKETCH's
  digitizer boundary;
- read-only `DBLIST` reporting;
- `WBLOCK` whole-drawing, named-block, and selected-entity exports; and
- FILES list-by-type, wildcard listing, delete, and rename operations on mapped
  host directories; QEMU confirms native rename/delete change only the
  disposable Samples floppy.

The QEMU evidence for the slice is deliberately narrower than its command
recognition. `HELP LINE` is the captured native page; other named help pages
have not been recovered. QEMU proves that DBLIST switches to text mode and
contains a LINE record, but its original formatting and pagination are not
matched. WBLOCK's three forms are compared with original output and are also
specified in Lean. `RES`/`RESOLUTION` share SNAP state, and Decimal precision
is verified in an AC1.40 DWG header.

`formal/` is an executable **behavioral** specification, not recovered source
code. It currently covers WBLOCK, DBLIST, Help/Files entry flows, units and
resolution state, and observed DIM/HATCH/SKETCH behavior. QEMU shows that DIM
writes ordinary LINE, SOLID, and TEXT records, not a dedicated dimension
record; the implemented HATCH LINE window case writes a clipped-line block and
insert for closed LINE/ARC loops, circles, and nested line-loop holes. The
upper semicircle closed by a diameter produces the same 16 clipped lines as the
native oracle. Other HATCH patterns remain unimplemented. The source-recovery
work did not produce an
AutoCAD Lean IR or a source-level model of `ACAD.EXE`.

The DWG/DXF work remains a strong base: all 16 AC1.2 sample drawings and the
AC1.40 sample drawings/backups in the render test parse and render, both writers
open in original AutoCAD, and the flat 1983 block-table model is documented in
the design spec. Recursive INSERT expansion has direct transform-composition
tests. BLIVET and SELEXOL render with 39,403 and 40,006 lit pixels respectively;
the 500-pixel corpus floor remains a nonblank guard, not a correctness oracle.

## Known limits and next work

1. DIM's `(ABCT)` sub-letters are now fully recovered under QEMU and are
   **not** dimension-type modes (no "angular", "baseline-geometry", etc.
   analogous to later AutoCAD's `DIMANGULAR`/`DIMBASELINE`): `A` sets the
   dimension arrow size (a single-shot setting that returns straight to
   `Command:`, never continuing into placing a dimension); `B`/`C` are
   confirmed **Baseline**/**Continue** — rejected with no prior dimension in
   the drawing, and once one exists both ask only for a second extension-line
   point (confirmed behaviorally; which extension line each anchors to was
   not isolated, since that needs decoded geometry, not just the prompt
   text); `T` toggles dimension text orientation (horizontal by default).
   There is no evidence AutoCAD 1.4 (1983) has angular/radial/diameter
   dimensioning at all. See
   [2026-09-30-dim-angular-recovery.md](superpowers/plans/2026-09-30-dim-angular-recovery.md)
   for the full recovery trail (including a dead end: live CGA text-mode
   screen reads don't work inside the drawing editor's graphics-mode screen —
   use `Session::capture_editor()` + `cga::Frame` + PNG rendering instead,
   proven working there and reused for the MENU work in item 3). What
   remains open: text placement/font-width rules beyond the two existing
   differential cases (one external-arrow, one text-split), and whether a
   valid (non-default) arrow size actually changes exported geometry.
2. Extend HATCH with native-observed pattern definitions and additional curved
   boundary differential cases. Closed LINE/ARC loop clipping and nested
   line-loop holes are implemented and have QEMU regression cases.
3. `MENU` rendering and mouse dispatch is in progress (not yet merged): see
   [2026-10-01-screen-menu-rendering.md](superpowers/plans/2026-10-01-screen-menu-rendering.md).
   QEMU recovery found AutoCAD 1.4's screen menu paginates by `MenuEntry`
   `repeat`-marker (`*`-prefixed) boundaries, not a fixed page size — pages
   are 19/18/19 items for `ACAD.MNU`, `NEXT` cycles and wraps, `< GO >`'s
   exact native mechanism is still unresolved (currently implemented as a
   simplification: reset to page 0). Implementing this surfaced two
   previously-unnoticed bugs now fixed: `ZOOM ALL` had no implementation at
   all, and the app's menu-macro dispatch only split on `;`, not whitespace
   (silently breaking 4 of `ACAD.MNU`'s 57 real entries: `ERASE L`,
   `zoom a`, `zoom w`, `zoom p`). Also surfaced and still open: `Editor::default()`'s
   LIMITS (`-10..10`) don't match native's real default (`0..12 x 0..9`),
   so a fresh drawing's `ZOOM All` differs from native from the first frame.
4. Keep `SKETCH` at the digitizer boundary until a digitizer input path can be
   observed or emulated. It presently accepts its record increment and then
   stops; it must not be represented as implemented drawing creation.
5. For every partial command, extend the Lean contract only after QEMU has
   established observable facts, then add Rust refinement tests and an oracle
   check where the original can be driven.
