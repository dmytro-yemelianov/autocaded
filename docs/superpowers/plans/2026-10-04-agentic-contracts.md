## Selection / LIST / REPEAT contract and acceptance

Root scope update: S1 preserves immediate LIST while unifying ownership/IDs/groups; selected LIST and general window selection are S2. The acceptance cases below describe the combined target. Do not block S1 merely because explicitly deferred S2 dialogue/window cases remain open; keep them visible in matrix/ledger. Existing typed-ID and mouse selection workflows must remain compatible in S1.

Use one document-order selection enumeration everywhere. A reasonable bounded Rust contract is one selection ID per live top-level entity or repeat group, excluding LOAD, erased records and block definitions. INSERT and REPEAT are atomic selection owners, not separate IDs per rendered instance. Do not claim this ownership policy is recovered original behavior.

1. Construct interleaved LINE, LOAD, BLOCK definition, erased entity, two-member 3x2 REPEAT, trailing CIRCLE. LIST, ID selection, LAST, ALL, mouse picks, window selection, selected highlighting, edit operators and API count/explicit selection count must agree. Distinguish logical selectable count from flattened member/primitive count if retaining both.
2. Check equivalent Item::Repeat and Entity::Repeat representations after codecs, erasure/OOPS and undo. A top-level group has one owner even when members are nested or carry OnLayer. A malformed/empty group must not be selected by vacuous all-points containment.
3. Pick a repeat member at a nonzero row AND column offset; resolve the group. Test negative spacing and translated INSERT inside REPEAT. Bound traversal/expansion; imported maximum dimensions must not hang the event loop. If a case exceeds safe bounds, return a clear unsupported/budget outcome rather than a misleading hit or partial edit.
4. Window means wholly within the rectangle (HLP “Within window”). Define Rust bounds for arc sweep, text/font bounds, INSERT and groups explicitly. No silent “origin alone” containment for a visible block or repeated group that extends beyond the window. Partial crossing behavior is not recovered here.
5. Multiple mouse picks accumulate until Return/GO, duplicates deduplicate, cancel clears pending selection without mutation/undo. Selection through typed IDs remains an extension and may retain its existing immediate-submit route. Verify native-window click, shared Session/API point/click route and command-string route deliberately.
6. LIST asks for selection, reports geometry/layer/group details for that selected owner, and does not mutate drawing/undo/dirty or creation history. Error/retry and cancel preserve preexisting state. DBLIST remains full database traversal and need not adopt selection IDs for nested members.
7. MOVE/COPY/ERASE/OOPS/BLOCK/WBLOCK selected groups apply to the whole group; one undo restores source record positions and geometry. Rotation/scaling of axis-aligned repeat storage needs either a proven representation conversion or an explicit rejection before mutation. Do not silently transform members but leave repeat spacings unchanged.
8. Group-incompatible CHANGE point mode, FILLET, BREAK, ENTITYAREA or HATCH forms must reject atomically unless deliberately implemented. CHANGE layer must recursively define what changing a group layer means. No unexpected panic from existing Entity-only assumptions.
9. Off-layer eligibility must be one shared policy agreed with L1. Recommended: IDs and explicit ALL/LAST retain stable logical owners; invisible geometry is not mouse/window selectable. Define whether LIST can inspect hidden IDs. Turning a layer OFF must not cause unrelated IDs to renumber.

## Layer visibility / color / persistence acceptance

1. Parse LAYER n; LAYER ON 1,2; LAYER OFF 1,2; LAYER COLOR x; LAYER ?. Decide inline and prompted input routes consistently. Invalid, empty, duplicate, mixed-valid/invalid and out-of-range lists must not partially change the header. Use 0..127 layers/0..254 colors if matching supported codecs; 255 is not an available color.
2. ON/OFF retain stored color. COLOR changes current layer color without implicitly changing visibility unless explicitly documented. ? reports deterministic layer/color/ON-OFF/current information and is neutral to drawing/undo/dirty. Undefined-layer definition/default and current-layer-OFF rules are native policy, not HLP-established facts.
3. Make visibility semantic Header state, included in PartialEq, snapshots and dirty baseline; one successful layer operation should have a stated undo policy. No-op/repeated state assignments should not create surprising undo entries. Undo restores OFF and color together as appropriate.
4. Render filtering must cover bare default-layer entities, wrapped entities, INSERT owners and children, repeats, erased members and solid/trace filling. Preserve ordered LOAD font/library state even if its record layer is hidden; LOAD is not drawable content. Explicitly test mixed visible/hidden block members and repeat instances.
5. Invisible geometry must not win mouse picks/window selection. Check shared GUI/PNG/RGBA results and selected highlighting after OFF. ZOOM All HLP specifically refers to all visible layers; if current bounds still include hidden geometry, document and queue the view fix rather than claim complete layer/view parity.
6. Both AC1.2 and AC1.40 DWG encoders must reject nonempty semantic OFF state unless evidenced mapping appears. Historical DXF must also reject it: modern DXF negative colors are not proof for this 1983 codec. Do not encode undocumented bits, use 255 (loses defined layer/color), or turn all layers ON while reporting success.
7. Typed try_write Result for DXF is a reasonable additive API. Migrate every production save/conversion/export caller to it. The public legacy write(&Drawing)->Vec adapter must call try_write(...).expect(a clear unsupported-state message), or change to Result; leaving it as a silent raw serializer is unacceptable. Keep the raw serializer private. The adapter bounds changes without touching excluded acad-oracle callers; document its panic and cover it with a regression. No production Session/MCP/CLI write should panic or silently drop state. Baseline production callers are acad-app/src/document.rs:37 and acad-app/src/api.rs:116 (direct DXF export).
8. For SAVE, END and WBLOCK in each format: existing destination bytes, document attachment/revision, saved baseline and pending exit must remain intact on unsupported OFF state. Exercise missing destination as well: no new/truncated file and no staging residue. END must not exit after encode error. ON all then save must succeed and reopen with geometry/colors intact.
9. WBLOCK snapshots must retain or explicitly reject all relevant visibility semantics; clearing off_layers while assembling an export is silent data loss. Selection of only visible layers does not automatically authorize discarding an OFF table. Decide any future reduced-table export policy separately.
10. Keep command matrix and spec honest: layer display support can be delivered while OFF persistence remains unsupported. No corpus run or encode-decode round trip can establish undocumented OFF parity.

## Review/validation gates and stopping rule

No repeated full tests after unchanged success. Root owns all integrated execution.

Maximum three audit/review passes per milestone. If evidence still cannot determine OFF/radius persistence, DIM placement, TRACE semantics or script units, list the missing fact and retain safe unsupported behavior; do not repeat unchanged searches.
