## P2 — standalone fallback's stack grows before the budget can stop it

`crates/acad-cmd/src/text.rs:113–145` collects a pending entity stack and follows every INSERT using `stack.extend(&block.entities)`. The 100,000 budget is decremented per later pop; neither pending references nor INSERT recursion/cycles are bounded. A compact drawing with block B containing N INSERT B members and one preceding root INSERT B adds N references on each recursive pop. After k visits its pending allocation is approximately k*(N-1), even though the pop budget has only spent k. With a large but file-representable block this can allocate multiple gigabytes before returning the advertised context error. Metric-dependent C/R/A and CHANGE on a standalone `Editor` reach this path. The app's registered runtime provider uses the separate renderer walker and is unaffected.

Use bounded iterator frames and INSERT-depth/cycle handling, or enforce a pending-stack allocation bound before every extension (including initial/root Repeat collection). Add a branching self-reference regression requiring a prompt error without large allocation or mutation. The fallback may conservatively refuse unresolved context; it must not allocate proportionally to branching times its full visit budget.
