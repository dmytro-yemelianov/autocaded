# L2 retained OFF mapping audit

Decision: **supported for bounded native persistence implementation; no implementation approval yet**. Three distinct evidence passes completed: existing notes/fixtures; retained static instruction paths; independent raw-byte/table/arithmetic validation. No original, guest, translated runtime or collector was executed. No evidence or code was changed. This replaces the earlier assumption that retained sources cannot establish a mapping.

Primary bytes: `corpus/System/ACAD.EXE` SHA256 `0080e343930b6fad30b588f05bacb6fb65783d7d560cdf2f116ca09fc70b45b1`; `corpus/System/ACAD.OVL` SHA256 `c2e1ee5b538e53df022dbb8aba6ab65a3946b8a332438bdaf39a3938a43e0da8`.

Independently compared all 1,348 instructions in the eleven named initial routines plus reader EXE:6701 against their original file offsets: zero byte mismatches (initial set 1,240; reader 108). This validates the recovered bytes, not a new execution trace. Recovered CFG itself explicitly leaves overlay residency unresolved; the conclusions below follow direct call/data references in one overlay at a time and the resident field table.

The EXE MZ header is 0x200 bytes. Its load segment is 0x1010 and data segment 0x1e25, giving DS file base `0x200 + (0x1e25-0x1010)*16 = 0xe350`. ## Recovered facts

1. **OFF is signed negation of a defined positive color, not a separate guessed bit.** OVL02_CODE:cb65 reads the LAYER prompt. DS:178a is `ON`, DS:178d is `OFF`; comparison-success paths cbda–cbde call cd63 with argument1 and cbfe–cc01 call it with argument0 respectively. The handler cd63 addresses `DS:47c3 + 2*layer`. At ce2c–ce32 it selects ON/OFF by that argument. ON negates a negative word at ce42–ce56; if the old word is255 it defines the slot from current color DS:47c1 (ce5b–ce77). OFF requires signed word>0, excludes255, then NEG AX and writes the result (ce7c–cea6). Repeated ON/OFF is therefore idempotent for ordinary defined nonzero colors. Undefined255 remains undefined under OFF. Zero remains zero; there is no negative-zero representation.
2. **The historical renderer consumes that signed state.** EXE_CODE:72eb loads the entity layer's DS:47c3 word at72f1–7302. Signed comparisons7307–7315 allow only values1..127 through the draw path; nonpositive and >127 values jump out. This corroborates negative=hidden and also limits any historical color-range claim.
3. **DWG AC1.40 writes the table words directly at0xC8.** EXE_CODE:680d writes a12-byte signature from DS:46fa, then loops descriptor indices1..42 in DS:4906, passing each address/size directly to the output helper atcf64 (686b–68b6). Original bytes at DS:46fa contain `AC1.40` and zeros. Independently decoded descriptors: index29=(47bf,2) at cumulative output0xc4; index30=(47c1,2) at0xc6; index31=(47c3,256) at0xc8. The sum ends at0x202, matching the routine's own position check. Hence the negative words are serialized verbatim, little endian, in the known128-slot table. The field-table derivation is stronger than merely observing a coincidentally constant address difference.
4. **The retained reader accepts the same table for AC1.2 and AC1.40.** EXE_CODE:691f matches signature strings via DS:49b2 version descriptors. Original table entries bind `AC1.2` to final field pointer48d4/header end0x1d8, and `AC1.40` to48fe/end0x202. EXE_CODE:6701 starts at descriptor0 in DS:4906, reads each field directly throughcd8d, and stops after the version's final field pointer (673e–677f). Both include index31 unchanged. This establishes the original1.4 reader's handling of signed layer words in AC1.2 files; it does not prove a separately executed AutoCAD1.2 producer/UI behavior. No new version-dependent OFF flag was found or is needed on these paths.
5. **1983 DXF has direct signed decimal support.** OVL01_CODE:24de emits DS:c3f=`LAYER,1\n` and current layer, then DS:c4c=`LAYERC,1\n` at26db. Its8x16 loop reads DS:47c3 words and formats them with DS:c56=`%d,` and DS:c5a=`%d\n` (270d–2758), preserving a negative word as a signed decimal. Parser OVL01_CODE:1cd4 writes the same8x16 table through2192 (1e22–1e9c). Routine2192 calls its scan helper with DS:b0a=`%d%c`, destination supplied by the table loop, establishing signed input as well. This is original keyword/comma DXF evidence; no modern negative-ACI convention is assumed.
6. **Historical command limits differ from current native policy.** cd63 checks requested layer>0 and <=DS:46f8. COLOR routineceb8 admits positive colors<=127 and updates current color47c1/current slot; current-layer routinecf6f makes a selected negative slot positive and defines255 from current color. Current Rust accepts layer0/colors0..254 and intentionally keeps a selected hidden layer hidden. Those existing native choices must not be retroactively described as recovered parity. The file table itself has128 entries including slot0, so table storage and historical command admissibility are distinct questions.

## Independent validation and remaining limits

Read-only census of24 corpus DWG/BAK files found16 AC1.2 and8 AC1.40 headers. Defined table words were0..64 plus unused255; none was negative. Existing retained inputs/actions/transcripts yielded no identified OFF-save-reopen fixture. Thus this audit supplies static program evidence, **not measured OFF export/reopen parity**.

Independent16-bit arithmetic: color1 -> OFF word0xffff (bytesff ff);7 ->0xfff9 (f9 ff);64 ->0xffc0 (c0 ff);127 ->0xff81 (81 ff). Negating again recovers the color. Unused255 is0x00ff (ff00), distinct from OFF1. Color0 maps to0 in both states. Color254 can be negated algebraically to0xff02, but original renderer's1..127 rule and command range do not establish254 as a supported historical visible color.

## Bounded implementation contract / acceptance handoff

Enough evidence exists to implement signed decoding/encoding for defined, nonzero historical-range colors1..127 in DWG AC1.2/AC1.40 and historical DXF. A minimal implementation may keep a checked refusal for native edge cases until their policy is explicitly resolved. Off-layer0 has a table slot but no recovered command-created OFF example; supporting its signed storage must be labeled a native extension, not original command parity. Off colors128..254 likewise require an explicit extension decision rather than silently claiming historical rendering compatibility.

Keep `Header.layers` positive colors and `Header.off_layers` separate if convenient: decode valid negative signed words to magnitude+OFF, and encode an OFF entry as negative magnitude. Preserve positive entries and255 semantics. Do not reinterpret255 as OFF; do not use a sign-bit OR (e.g.0x8007 is not NEG7); do not clear OFF on save. Validate OFF sets against defined slots and representability before staging. In particular **OFF color0 must remain an explicit checked error** unless a separate supported representation is recovered. Negative sentinel/invalid magnitudes (including-255 and-32768) need an explicit error contract; no unchecked abs overflow or truncating cast.

Required checks before implementation acceptance:

- Exact known signed bytes/text at several nonzero colors, both DWG revisions and historical DXF; reopen preserves magnitude, visibility and other slots/header fields. Label constructed tests as synthetic static-contract fixtures, not original OFF outputs.
- Existing24-file corpus still decodes/reencodes under its established compatibility criteria; positive0 remains as previously supported native data, distinct from representable OFF.
- Both checked and legacy serializer entry points handle unsupported states explicitly; SAVE/END/WBLOCK/API failures preserve destination, attachment, baseline/dirty state and original in-memory OFF state. Supported OFF saves must update/reopen normally.
- Malformed negative magnitudes/undefined OFF/native edge states fail before partial output or disk replacement. ON/UNDO restore saveability for unrepresentable OFF0.
- API, rendering, picking/highlight, undo and reopen share the semantic set; persistence must not accidentally change the separately declared current-layer-selection policy.
- Update docs/native-layer-policy.md's blanket “no retained mapping” statement only with this provenance, static-evidence limitation, supported range and residual refusal cases. Separate L2 implementation status from this completed audit.

Missing evidence for full parity: an existing retained original-generated OFF export/reopen fixture (or a separately authorized future measurement), original behavior for the native layer0/color0/>127 extensions, and a decision on reconciling native current-layer selection with recovered auto-ON behavior. None blocks bounded signed persistence for the recovered range. No further unchanged-source audit is proposed.
