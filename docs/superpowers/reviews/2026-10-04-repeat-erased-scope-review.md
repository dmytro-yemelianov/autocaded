# B3b selected-address scope and negative-marker playback

Decision: **the bounded static question is materially resolved for ordinary top-level REPEAT geometry, but does not establish original whole-owner ERASE persistence.** The inspected original path selects source members, not a REPEAT start-marker owner. Negative records are skipped individually during playback; a negative start marker does not hide its positive descendants. The current Rust choice to select/edit one stored REPEAT owner remains a native policy. Do not implement a purported historical whole-group sign encoding from this result.

Three distinct passes: (1) ERASE/list/iterator producer chain; (2) REPEAT playback/cache ownership and sign branches; (3) independent original-byte/dispatch-table validation. No original, guest, translated runtime or collector was executed. No code or evidence was changed. This is a sharply scoped follow-up to b3-contract-review.md, not a new broad grammar audit.

## 2. What address repeated geometry puts into that cache

The original EXE rendering switch at3d01 was independently decoded. Key5 branches to3cc2 (`CALL3dcb`); key6 branches to3cc8 (`CALL3e83`). Type1 branches to3caa/3d44, eventually the line-geometry path192d. No recovered name assumption is needed for the marker dispatch.

REPEAT start3dcb pushes the previous repeat counters, resume address and displacement; gets the current stream position via78dc into52e5/52e3; increments repeat depth4256 and displacement nesting4486; initializes counters. It **does not set the cache owner address425e/425c or emit a cache boundary/geometry record**. ENDREP3e83 updates column/row offsets and counters, reseeks through3fd1->76b7 for further copies, then restores the stack. It likewise does not create a marker-owned selectable geometry address. Nested starts use the same stack mechanism; this is stronger playback evidence than the earlier balance-only c7d1 check, although no original nested fixture was executed.

The main reader7713 takes physical current-record address58e7/58e5 from793b and stores it into58d5/58d3 at773d–774b. The line geometry path192d, at1e12–1e70, chooses the active enclosing reference address425e/425c when nonzero; otherwise it passes **current physical leaf address58d5/58d3** to cache writer7154. It also passes the current entity layer42c0, with an existing special127 inheritance branch. Geometry primitive/type/coordinates are passed separately.

7154 starts/flushes a cache boundary when address or layer changes and records the primitive.7425 writes a boundary type-1;7482 places the physical address in that boundary;7589/7233 recover it as described above. Thus all displayed copies originating from the same ordinary source leaf can lead to that same physical leaf address. Selecting one displayed copy and erasing its source leaf hides all copies of that source leaf; it does not require negating either marker. This is a direct dataflow conclusion, not a newly measured GUI result. Cache identifiers may vary across repeated visits; this audit does not assert one historical numeric ID per source leaf.

The enclosing-reference exception is real: INSERT handler43db sets425c to the reference's current address when entering its block, so geometry inside an inserted block can select the INSERT source record. That is not evidence that REPEAT markers acquire ownership. The ordinary reset46f3 clears425c, and the REPEAT handlers do not replace it.

Consequently the question “which addresses belong to one selected REPEAT owner?” has no such owner on this traced original top-level geometry path. A selection matching several repeated source members may produce several member-address tuples; the list producer does not append the start/end marker addresses. The native Rust canonical-group selection contract intentionally differs.

This also supports treating bare marker layers as preserved metadata rather than as new native owner gates: the start/end handlers do not perform their own layer-color visibility gate. The visible line path gates the selected leaf/inherited reference layer. This does not establish all original INSERT/layer127 policies or justify changing the existing native wrapper policy.

## 3. Negative-marker playback is independent record skipping

EXE:793b calls the physical reader3770, which already decodes fields using abs(type). At799e it reloads signed42be, compares to0 at79a2, and takes JLE79aa to7ce3, which loops back to the next physical read at793f. The original bytes are `8b06be423d00007e03e90300e93603`. **Every nonpositive record is consumed and skipped before it reaches the rendering dispatcher.** There is no negative-start depth scan or descendant suppression on that branch.

For a top-level physical stream `-REPEAT, +LINE, +ENDREP`, the negative marker is skipped, the positive LINE is returned normally, and the positive ENDREP reaches3e83 without an open repeat. That handler tests depth<=0 and reports/returns at3e86–3e9e. Thus “negative start means erased whole group” is positively contradicted by this path. Likewise skipping a negative ENDREP does not perform its positive close/reseek behavior. Arbitrary partially signed structural streams cannot be decoded as a whole erased owner merely by observing one sign.

Fully negating a group's start, leaves and end would cause the original record iterator to skip every one; retaining positive markers and negating all drawing/resource leaves would produce a different physical stream. Both are possible constructed byte patterns, but this selection chain proves neither is the original representation of a native whole-owner erase. Do not promote a plausible constructed result into recovered command parity.

## Abstract supported contract and remaining decision

Recovered contract: physical type sign belongs to **one record**. Decode abs(type)'s fields and retain sign/layer/address; negative ordinary source members remain in place but do not render. Positive REPEAT markers drive a stack of repeated traversal; a selected repeated member resolves through the cache to its source leaf (or enclosing INSERT reference) and ERASE/OOPS toggles that selected record's sign. Markers are unchanged by that ordinary member selection. The top-level ADDER negative LINE/INSERT fixtures remain consistent with this rule; no negative-marker original fixture was found in the prior bounded corpus audit.

For native B3a, preserve marker metadata and correct child headers as already approved. Do not silently discard erased members or negative structural records while assembling groups; preserve their physical status or return a named unsupported semantic error. Do not treat negative marker alone as Item::Erased(Repeat).

For native B3b, the outstanding decision is **how to persist the Rust whole-owner erase policy in a historical stream without losing logical owner status, member erasure states, metadata, resource effects or reopen behavior**. The original selection path cannot supply a one-owner mapping because its selection unit differs. Options require a separately explicit native persistence contract and independent review; neither marker-only nor all-record negation is approved here. If claiming an additional original group-erase command path, provide its direct selector/cache producer or retained original file evidence; do not keep rereading this unchanged path as though a hidden expansion were established. Safe refusal remains interim safety and is not completion of native B3b functionality.

Acceptance for any later approved policy must distinguish: partial member erasure, whole native owner erasure, nested mixed live/erased members, original signs, start/end marker layers, first-leaf layer, enclosing INSERT roots, LOAD effects and OOPS/UNDO in-session versus after reopen. Constructed tests can validate that declared native policy, but cannot be labeled original erase fixture parity.

## Coordinator proposal critique — explicitly native uniform-negative owner policy

After the static audit, root proposed a new **native** contract: serialize a whole erased Repeat by negating every lexical marker/member; reconstruct an erased logical owner only from a balanced uniformly negative subtree; keep partially erased live-group states unsupported. This is coherent with the recovered record-level skip behavior, subject to the following conditions. It is not inferred original ERASE selection parity and is not yet implementation approval.

1. **Model placement must be explicit.** `Item::Erased(Repeat)` is legal at a drawing-item root. An all-negative subtree inside a live Repeat or a live Block cannot silently become a top-level erased Item, nor disappear. With the current Vec<Entity> representation, reject that location until erased member state is represented. An all-negative nested Repeat inside an all-negative outer root is ordinary nested metadata beneath the single outer erased Item; its sign will be reapplied recursively when written.
2. **Uniform means the complete lexical subtree.** Both start/end markers and every ordinary member, recursively, must be negative. Any positive member/marker inside that root must produce a named unsupported mixed-sign error; do not salvage a partial drawing. Positive live groups with any erased member remain the declared residual limitation. Structural balance/block boundaries, physical count/end and depth caps apply independently of sign. Negative structural blocks remain outside this Repeat-specific contract.
3. **Referenced resources are not lexical members.** Negating an INSERT record suppresses that reference. Do not negate the referenced block definition or other transitive dependencies elsewhere in the drawing. Negating an enclosed LOAD suppresses its resource effect, consistent with the existing native Item::Erased owner's no-traversal behavior; later live entities retain whatever earlier resource context actually remains.
4. **Decode all fields before accepting erased state.** Truncated/nonfinite/invalid dimensions, invalid layers, unknown absolute types and abs(-32768) need the same checked treatment as live records. Negative sign is not a validation bypass. Preserve marker metadata and actual first-child layers. Existing unsupported runtime owner-wrapper guards still apply; do not use uniform erasure as a way to strip an OnLayer(REPEAT) owner that OOPS would need later.
5. **Resolve empty groups deliberately.** Uniform negativity is vacuously true for a negative start/end with no members. Either permit empty live/erased groups consistently as a declared native contract, or retain a consistent named refusal on both paths. Do not accidentally claim original empty-group behavior from this condition.
6. **DXF is a distinct live-export contract.** Omitting Item::Erased—including the whole group—is consistent with the existing ordinary-erased omission only if docs/API explicitly describe the loss of erased geometry/history. It is not an erased-group roundtrip. Omission must occur as one whole erased subtree, with no leaked LOAD/member records. Live malformed or unsupported owner content remains checked. WBLOCK selected groups remain live exports under the existing command contract.
7. **Lifecycle claims remain narrow.** In-session OOPS/UNDO can restore the original model; reopen has no retained editor OOPS history. A uniformly negative legacy byte stream may be interpreted under this declared native rule, but it must not be called proof that the original author erased one group owner. Re-encoding the accepted stream must preserve its uniform record signs and fields.

Required policy tests: all-negative flat/nested root exact bytes and reopened hidden state; direct physical sign/count/layer assertions; one positive child/start/end at each nesting level rejected; all-negative child inside live Repeat/Block rejected; negative INSERT leaves shared definitions/live references intact; negative LOAD has no later font effect; malformed erased fields still rejected; empty policy; unsupported explicit owner wrapper; SAVE/END/WBLOCK/API/legacy adapters and atomic failure; DXF omission without resource leakage; OOPS before save and absent history after reopen distinguished. These synthetic native-policy cases supplement held original corpus checks rather than replacing them.

Contract critique verdict: **conditionally supported native design**, pending coordinator acceptance of these boundaries and exact source/test review. Parent B3's original group-selection parity and partial-erasure model gap remain open; this is more than refusal-only safety but must not be labeled unrestricted group persistence.
