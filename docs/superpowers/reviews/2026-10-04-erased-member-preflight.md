# R4 B4 erased ordinary-member design preflight

Decision: **contracts-ready for a bounded ordinary-member implementation**, subject to exact source review. This is not implementation verification. Prior recovered physical sign and playback evidence is reused; no additional original-source search or execution is required. Original physical reader/writer dispatch by magnitude preserves fields; EXE:793b skips each negative record independently; ordinary source-member selection/ERASE dataflow was recorded in `b3-erased-scope.md`.

## Representation and accepted boundary

An `Entity::Erased(Box<Entity>)` member wrapper can express negative ordinary records inside a live Repeat or Block while preserving their type, fields and layer. Prefer one canonical decoded representation `Erased(OnLayer(ordinary))`. Keep Item::Erased for top-level erased owners and its session restoration semantics. No new selectable ID for a member; top-level canonical IDs remain stable. Define checked treatment of noncanonical wrapper ordering rather than silently losing a layer/sign; repeated erased wrappers and erased structural Entity::Repeat wrappers remain outside this ordinary-member scope.

DWG physical count includes each erased ordinary record, and the signed header writes only that leaf negative in an otherwise live group. Existing independent start/end marker layers stay intact. Live all-erased-member groups are distinct from uniformly erased owners: positive structural markers plus negative leaves can now be preserved as a live container with no visible leaf. Erased LOAD and erased INSERT must have no resource or referenced-geometry effects. A negative INSERT's referenced definition remains an independent stored definition and may still be referenced by other live objects.

## Ambiguous whole-owner erasure

The existing all-negative owner representation cannot retain whether an individual member was already erased before the owner was erased. Smallest counterexample: live Repeat `[Erased(LINE A), LINE B]` becomes Item::Erased(Repeat(...)); writing every physical record negative gives the same stream as an erased owner containing two originally live lines. Reopening then in-memory whole-owner restoration cannot distinguish A's prior state. Therefore DWG checked save must refuse Item::Erased(Repeat) containing any member Erased state, including nested Repeat descendants. Do not strip tags, revive A, invent a bit, or infer original whole-owner erasure parity. BLOCK's retained erased source and ERASE of such a whole owner inherit this boundary. In-session OOPS/UNDO must still recover exact source wrappers/metadata; failed saves cannot add history or alter destinations/attachment/baselines.

DXF may omit whole erased owners as the established live-only export policy, provided its shared validation explicitly accounts for the different format contract. A stricter checked refusal is safe but must be stated as a native export limitation. Do not let differing format behavior accidentally relax DWG ambiguity checks.

## Traversal policy and integration checklist

- Rendering, visibility, mouse/window picking, highlights, anchor/bounds, HATCH extraction, font lookup, LOAD-only export projection and live entity counts must skip erased ordinary members. Resource scans must stop at Erased without unwrapping and executing a hidden LOAD/INSERT. Plain OnLayer visibility bypass for resource state must not bypass erased state.
- Stored validation, DWG count/encoding and source-preserving clone/undo traverse the erased payload under explicit ordinary-only rules. Corrupt erased fields/layers, nested erased wrappers and structural payloads require named refusal. A helper that strips both OnLayer and Erased indiscriminately risks leaking erased geometry; separate storage traversal from live traversal.
- Whole-owner transforms/layer changes must preserve the sign wrapper. Whether hidden member coordinates/layers change with an owner is an explicit native policy; document and test that choice rather than claim original selected-leaf parity. A coherent whole-owner transform may transform all stored member coordinates while leaving erased state intact. Live anchors and operations requiring visible geometry must ignore erased members and fail atomically when none remains.
- Report live/member counts consistently; if erased stored records are shown diagnostically, label them rather than count them as live selectable geometry. Top-level owner IDs may still exist for a live container whose leaves are all erased; its picking/bounds/anchor behavior must be empty and safe.
- New exhaustive cases are needed in model visibility, command entity/geometry/selection/report helpers, render geometry/resource/budget walkers, app text measurement context, standalone text context, WBLOCK projector, codecs and undo/history handling. Preserve strict DIM/native fixture comparisons and the existing independent-marker constructor metadata.

## DXF empty-container hazard

Smallest counterexample: positive REPEAT marker, one negative LINE member, positive ENDREP. If DXF skips only that member but emits the marker pair, it produces an empty Repeat rejected by the current parser. The same occurs recursively when all surviving child groups become empty. **Before staging, either prune newly empty Repeat subtrees under an explicit live-export policy or checked-refuse.** Do not produce unreadable files. LOAD is exportable content even with no visible geometry; a Repeat containing a live LOAD is not empty. Empty Block bodies have their own existing grammar and should not be conflated with empty Repeat rejection. Pruning must not discard ordered LOAD effects, marker metadata of retained groups or independent block definitions.

## Required acceptance cases

Independent raw live-Repeat and live-Block streams with negative LINE/TEXT/LOAD/INSERT members; both revisions and exact signed header/field/layer/count retention. Nested live groups with mixed live/erased ordinary leaves. All-erased-member live groups and recursively empty DXF projection. Erased LOAD followed by live text and erased INSERT referencing a LOAD-bearing block must leave the prior resource context unchanged. Positive-marker/member wrappers preserve render/pick/count behavior before/after DWG reopen; DXF exhibits explicitly live-only omission. Whole-owner erase with prior member erasure must refuse DWG atomically, recover exactly through OOPS/UNDO, and preserve old destination/attachment/baseline. Reject malformed signs/wrappers/fields without recursion or allocation regressions. Validate geometry helper behavior for no visible anchor, and keep original ordinary erased top-level/canonical owner behavior unchanged.
